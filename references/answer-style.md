# 作答风格与样例校准

先从题干、模板和评分标准判断交付文体；领域决定术语与证据惯例，不决定句子必须复杂。同一作业可混合多种题型，逐题处理。不要按“母语/非母语学生”或学历给用户预设文风。

| 任务 | 默认建议（服从课程与用户明确要求） |
|---|---|
| 问答、选择并说明理由 | 先直接回应，再写必要理由/机制；避免背景铺陈和讲课式总结 |
| 比较 | 对应相同维度写差异及其影响，避免分别长篇介绍却没有比较 |
| 计算 | 已知与必要假设、公式、代入、单位和结果；解释影响结果的条件 |
| 实验报告 | 遵循模板，清楚区分方法、结果与讨论，保留分析及引用 |
| 论述/文献综述 | 论点、证据、分析和限制；需要展开时不能一律改成短答案 |
| 编程 | 交付代码与题目要求的说明；报告测试证据，避免无关讲解 |

重点是回答完整且直接，不是追求最短。题目要求解释时保留机制链；评分内容由题目和标准推断并标明依据，不能声称知道未提供的评分点。不得为显得专业额外堆砌限定词、背景或术语。

题干让选择时可写 “I choose … because …”，让比较时可写 “Compared with …”，但不要把第一人称套到所有题目。需要客观文体或课程禁用第一人称时遵守要求。示例：题目要求选择一种方案时，直接写 “I choose method A because it meets the accuracy requirement and takes less time.”，而不是先泛泛介绍方法选择的重要性。

## 校准一次，再推广

有适用的已确认偏好或用户提供的目标样例就直接采用。没有时，开场给具体建议而不是抽象标签，例如“这份是短问答，建议简单句、直接回应、保留必要解释”，允许用户选择更详细或更正式的表达。

风格仍不确定且整份输出成本较高时，从当前作业选一个短答案或段落作为样例，集中请用户确认或调整，再推广。样例只确认表达，不启动逐题辅导；先完成文件模式也适用。用户已给样例、明确接受建议或要求直接完成时不再强加样例等待，按已明确要求推进。

用户说“太像教材”“太啰嗦”时，定位具体变化：回答视角、句子复杂度、无关背景或重复解释。不能默认等于删内容、减字数。说明将怎样改，保留必要答案逻辑。检查最终答案是否覆盖题干所有子问、符合文体、沿用课程术语并且没有辅导口吻。
