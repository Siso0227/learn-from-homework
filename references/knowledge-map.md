# 知识依赖、状态与图谱

## 最小课程地图

按课程维护概念与联系，优先复用已有私人地图。概念使用稳定标识或名称/别名，避免同一概念重复建节点；课程之间不无依据合并。最小记录包括：概念、必要前置、课程来源及位置、关联题号/例题、本作业覆盖情况、学习状态与证据、待补缺口/下一步。不要把操作步骤画成概念依赖；跨分支联系按需用有说明的关系线表示。

每题开始关联已有节点；识别最近真正阻塞推理的前置缺口，必要时向基础方向追溯，用短诊断核实，不无差别复习整章。

## 证据驱动的状态

| 状态 | 判断依据 |
|---|---|
| 未检验 | 没有足够用户回应；未涉及、没回复或只看过答案都不能判为不会 |
| 可在提示下完成 | 用户借助提示完成相应任务，记录提示程度和题目 |
| 可独立应用 | 无关键提示完成代表性问题，并能说明必要逻辑；注明已验证题型/条件，不扩大到所有迁移情境 |
| 存在具体困难 | 实际回答暴露缺口，记录困难所在，不作固定能力标签 |

复述原理只支持对应理解证据，不等同独立计算或迁移。一次猜对或直接复制答案不足以升级。每题检查有无新证据，有变化才更新，报告类似“提示下完成 → 在本类题中可独立应用；依据：独立完成变式并说明条件”。无变化可省略输出，不制造进步。先完成文件模式中，先记录作业覆盖，用户掌握仍为未检验；后续辅导再取证。新错误也可使状态调整，保留简短历史而非整段对话。

## 回顾与范围选择

作业后提供简短回顾，并在需要图谱时确认范围：
- 作业图谱：本次涉及的知识及必要前置，突出题号与解法链。
- 课程全景＋作业高亮：梳理已提供材料的重要知识，再高亮作业使用部分；注明实际覆盖材料及未提供/未检查部分，不宣称完整涵盖整门课。

重要性依据学习目标、章节结构和教师明确强调，不虚构考试重点。全景梳理是额外工作，不默认每次执行；时间紧先交作业，再处理图谱。偏好明确且资料范围清楚时不重复确认。

## 视觉编码与 XMind

把三种信息分开：层级表现主题组织；有说明的箭头表现前置依赖；底色/边框区分本作业涉及和其他课程内容；图标/文字表现掌握状态；题号标签表现题目关联。必须有图例，不只靠颜色或红绿区分。未涉及不等于不会；本作业覆盖也不等于已学会。来源、例题和学习证据放节点备注，避免主图过密。

按用户需要生成独立 XMind 文件，遵循所用工具可核实支持的格式；不假设付费工具或自动具备导出能力。交付前检查文件可读取、节点/关系与备注完整；若有 XMind 预览能力还要检查文字、颜色及连线。不能验证应用内显示时明确验证范围，不能宣称已打开验证。无法可靠生成 `.xmind` 时，先说明并提供 Markdown/OPML 层级大纲等替代选择，标明哪些颜色、关系线或备注不能保留，不把其他格式改扩展名冒充 XMind，也不承诺未经核实的导入效果。

实际课程图谱、截图和学习证据属于私人材料。默认在对话更新地图；用户要求导出即授权在其私人工作区生成本次图谱，但长期持续保存仍按用户已确认的范围执行。持久记录放用户选择的私人课程目录，或 skill 的 `private/courses/` 中引用；读取与更新要保留既有来源、证据和范围，不上传到公开仓库。
