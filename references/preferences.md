# 本地私人偏好

## 保存位置与范围

路径相对于实际调用的 skill 安装目录，不写死电脑路径：

```text
private/
  user-preferences.md       跨课程通用的教学/表达偏好
  task-types/<type>.md      同类任务，例如短问答或实验报告
  courses/<course-key>.md   本课程要求与局部偏好
```

这些文件在用户使用时按需生成，公开包不附带真实记录。当前任务临时要求默认留在对话；经同意保存课程进度时，可引用用户选定的私人课程目录，不复制全部课件或作业。课程标识不清楚时先核对，不能将不同课程混在一起。使用多个安装副本时说明各自记录不互通，不自动访问别的副本。

## 识别、确认、保存、读取

1. 当前明确反馈先应用于当前任务，长期保存不作为继续工作的前提。
2. “这次”视为临时要求。“以后我的短问答都……”已明确长期意图和范围，可保存并告知。“这个太像教材了”只足以支持本次修改；要推广先问：“只用于本次，还是以后同类问答题也这样写？”
3. 不将多次观察自动升级为事实。向用户概括候选偏好，确认内容和范围后才写入，不重复询问已经明确的授权。
4. 写入最小必要记录：偏好内容、适用范围、用户确认日期/来源、必要的例外。公开示例与真实用户记录分开，不保存整段聊天、账号密码或无关个人信息。暂定推测保留在对话，不写成长期默认。
5. 合并相关条目；有冲突时根据当前指令处理，只有旧记录也要改变才更新对应条目。用户可查看、修改、停用或删除；只处理其指定范围。
6. 写入后重新读取确认内容和范围，简短报告“已保存什么、用于哪里”。写入失败或无权限时明确未保存，提供可复制摘要或用户选择的私人替代位置，不声称跨对话已记住。

记录示例（虚构）：

```markdown
# 已确认偏好
- 内容：先给一个具体例子，再解释抽象规则。
- 范围：跨课程辅导；不规定正式作答文体。
- 来源：用户明确要求以后沿用。
- 确认日期：填写实际确认日期。
```

## 更新与分享保护

- 更新通用 skill 时先检查目标 `private/`，在用户控制的私人位置做好备份，更新后确认记录仍在，再报告结果。只替换通用文件，不用清空目录或强制覆盖方式重装；更新工具行为不明时先保护记录。
- `.gitignore` 只能防止 Git 自动跟踪，不能保护 ZIP、已跟踪文件或网页上传。分享/上传前必须检查完整文件清单，显式排除 `private/`、真实课程资料及学习记录；不要整目录无差别压缩或上传。
- 如果私人文件已被 Git 跟踪，停止发布并告知用户，不能只加忽略规则就称其安全。移除跟踪或处理历史应单独处理，不能把含私人数据的提交推送出去。
- GitHub 更新不会自动同步到用户本地；本地偏好也不会自动上传、跨设备同步或写回公共规则。需要迁移时由用户选择私人传输方式，不通过公开仓库同步。
